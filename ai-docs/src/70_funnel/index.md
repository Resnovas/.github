## Funnel tooling contracts

Canonical adoption instructions: `docs/house-funnel.md`. This repository's bounded feature inventory and assertions: `docs/verification.md`. Delivery sequencing and owner decisions: `docs/funnel-timeline.md`.

Run `node --run verify:static` before `node --run verify`. The first runs shared ESLint rules, Markdown budgets and source/registry coverage; the second preserves all previous consistency and test gates. Setup exclusively creates a pre-commit hook only once both package scripts exist. It verifies the staged snapshot and never rewrites an existing hook. Evidence metadata and digest reads share one open descriptor; a dedicated publication directory must have no concurrent writers through upload.

The house is non-production Node tooling. Its shared `contracts` ESLint export is adopted with each product's existing TypeScript parser and documentation checks. No runtime feature flag is needed. `funnel` adds source-inspection policy and informative JSDoc without replacing Nx or other rules.

`contracts` enables all 20 documentation rules listed in `docs/house-funnel.md`, including parameter/return/throw/template contracts, sentence-form descriptions, public/exported examples and all declaration/callback shapes. Execute `test/funnel-lint.test.mjs` for each rule's accepted/rejected fixtures. Put examples at export boundaries (including aliases/re-exports), on public members of directly exported classes/interfaces, and on other declarations marked `@public`. Preserve reviewed source exclusions and Eventiva's rationale/zero gate and smartcloud's declaration/example checks. Keep semantic accuracy and meaningful in-body explanations in guidance; syntax lint cannot establish either or execute examples.

Every rule in the shared `jsdoc` plugin delegates to the vendor unchanged except for diagnostics attached to the exact canonical licence header at the beginning of a file (after an optional shebang). Both exports share that plugin object; the existing `house/require-description` and `house/match-description` aliases remain compatible. Additional consumer-enabled `jsdoc/` rules receive the same exemption. When composing an existing vendor preset, replace only its raw `plugins.jsdoc` binding with `funnel.plugins.jsdoc`, preserving its rules/settings and parser/processor. The canonical template ships this behavior to every consuming Node repository through normal sync, not a product-specific override.

The synced module location under `tools/lint/` anchors the repository root and adjacent `tools/license/header.txt`; ESLint can run from the root or a nested package. Resolve relative input filenames against ESLint's cwd, then compare the current-year header with the repository-relative filename. Root/nested-cwd fixtures preserve noncanonical-header and declaration rejection. All 20 rule fixture pairs run with and without headers; additional rule/autofix and rendered consumer fixtures prove legal text stays intact while invalid settings and declaration diagnostics remain visible. Do not exempt top comments generally, suppress whole files, or let headers stand in for declaration JSDoc. Keep the licence gate required.

The document inventory selects tracked and non-ignored untracked Markdown before buffering and has no fixed subprocess-output cap. Within `docs/`, only balanced standalone Linear/Planning generated-region pairs outside code fences are omitted from budget accounting. Count all authored text surrounding those regions together. Malformed regions remain fully counted; unmarked documents receive no exemption. Keep the generator drift checks required: marker recognition does not prove generator ownership or authorize moving authored content into generated regions. Regression fixtures exceed Eventiva's reported 3,303,046-byte inventory and retain failing authored-line/byte boundary controls.

AI-03 and AI-31 reserve sign-off for humans except for the documented owner-session exception, which must be present in loaded personal instructions. The existing commit-msg and smartcloud DCO checks compare non-AI signer email with commit author email; identity matching cannot prove consent. Never treat the policy's quotation as authorization. Readiness and merge remain human-owned.

`house-readiness.yml` is a metadata-only `pull_request_target: ready_for_review` guard, not a PR-code execution or required head check. With only `pull-requests: write`, it restores drafts converted by `linear-code[bot]`, paginates current readiness history and preserves later human decisions. Failure to read or restore fails visibly. It becomes active after normal base-branch adoption, cannot replay old events, and cannot atomically exclude a simultaneous human transition. The actual workflow body has accepted/rejected API fixtures in `test/workflows.test.mjs`. Linear's personal auto-convert setting reacts to review requests (including Copilot) or approvals; issue state automation is separate. Avoid requesting reviews on drafts and verify draft state at handoff. The account owner can disable that one setting while keeping Linear to avoid a transient ready window; no personal setting is changed by the house workflow.

`scripts/verify-funnel.mjs collect` executes the Markdown entry's contract tests without cached results. It binds HEAD plus the matching index tree, compares actual TAP test names/counts to documented assertions, and publishes only synthetic allowlisted outcomes in `.verification/publish`. `check` validates publication structure and file digests while preserving a failed collector outcome. `registry` compares the Markdown interface list with discovered shared tools. `FUNNEL_BASE_SHA` selects the comparison commit; it must be a full SHA. Without it, local collection compares to HEAD's parent. No affected interface produces an explicit not-applicable result and no upload, never a passing empty feature manifest.

Executable examples live in `test/funnel.test.mjs` and `test/funnel-lint.test.mjs`: matching/mismatching build-info, installed-hook staging/failure behavior, lint rejection/acceptance, registry inventory drift, empty proof, stale digest, wider affected selections and modified evidence bytes. These exercise public tool contracts rather than asserting source strings disappeared. Downstream browser/native proof remains the owning product's responsibility.
